# Midnight development environment

## Windows first — this is not optional

**Midnight development is not supported natively on Windows.** Both sources say so directly:

- [Install the toolchain](https://docs.midnight.network/getting-started/installation): *"Development is supported on Linux and Mac. Windows is not supported natively at this time, if you are using Windows, development through WSL is recommended."*
- [Midnight Expert](https://docs.midnight.network/ai-integration/midnight-expert): *"macOS or Linux. On Windows, run everything inside WSL2."*

This machine is Windows 11. Everything below happens inside WSL2.

```bash
wsl --install -d ubuntu
```

Run that from an **elevated PowerShell**. It takes 5–15 minutes and prompts for a UNIX username and password (the password will not echo — that is normal). Verify with `wsl -l -v`.

Then:

1. Install Docker Desktop and enable **WSL2 integration** for the Ubuntu distro
2. Install the Compact toolchain **inside Ubuntu**, not on Windows
3. **Keep project files on the Linux filesystem** (`~/projects/...`), not `/mnt/c/...`. Cross-filesystem I/O is slow enough to matter when compiling circuits
4. Launch Claude Code from the Ubuntu shell if you want the Midnight Expert plugins to work

Full guide with screenshots: [Windows Compact setup](https://docs.midnight.network/guides/windows-compact-setup).

## The toolchain

```bash
curl --proto '=https' --tlsv1.2 -LsSf \
  https://github.com/midnightntwrk/compact/releases/latest/download/compact-installer.sh | sh
```

Reload the shell (`source ~/.bashrc`), then:

```bash
compact update 0.31.1
compact --version
compact compile --version
which compact
```

If `compact` is not found, add it manually: `export PATH="$HOME/.compact/bin:$PATH"`.

Editor support: [VS Code extension](https://docs.midnight.network/compact/compilation-and-tooling/vscode-plugin) · [Neovim](https://docs.midnight.network/compact/compilation-and-tooling/neovim-setup).

## The proof server

It generates zero-knowledge proofs from your private data, which is why **it always runs locally on port 6300 regardless of which network you target**.

```bash
docker run -p 6300:6300 midnightntwrk/proof-server:8.1.0 midnight-proof-server -v
```

That command occupies the terminal. Background it or use the local devnet stack instead.

## Scaffolding

```bash
npx create-mn-app [project-name]
```

Prompts for **Contract** or **Full DApp**:

| Choice | Templates |
|---|---|
| Contract | `hello-world` (default; bundles a local devnet and the `--network` flag), `battleship` |
| Full DApp | `bboard` (default), `leaderboard` (React + Lace, in-browser proving) |

`hello-world` is the right starting point. Only it ships the bundled devnet.

Alternative: clone an official example directly — [example-bboard](https://github.com/midnightntwrk/example-bboard), [example-zkloan](https://github.com/midnightntwrk/example-zkloan), [example-private-party](https://github.com/midnightntwrk/example-private-party), [example-battleship](https://github.com/midnightntwrk/example-battleship).

## The DUST timing trap

Transactions cost DUST. DUST is generated by holding registered NIGHT — you cannot buy it, and it is not transferable.

**Registration through the cross-chain path (cNIGHT on Cardano) takes about 12 hours.** On a local network it is about 5 minutes.

Two consequences:

- Plan any demo on `undeployed`, or fund testnet wallets a day early
- For anything consumer-facing, implement [DUST sponsorship](https://docs.midnight.network/guides/dust-sponsorship) — the operator holds NIGHT and pays fees so a user with zero DUST can transact from their first click. Reference implementation: [example-private-party](https://github.com/midnightntwrk/example-private-party/blob/main/docs/SPONSORSHIP.md)

## Version pinning

Mismatched versions are the most common non-obvious failure in this ecosystem, and the symptom is usually a silent failure rather than an error. Pin everything. From the [compatibility matrix](https://docs.midnight.network/relnotes/support-matrix), 29 August 2026:

| Component | Version |
|---|---|
| Compact devtools (`compact`) | 0.5.1 |
| Compact compiler | 0.31.1 |
| Compact runtime | 0.16.0 |
| Compact JS | 2.5.1 |
| Midnight.js / testkit-js | 4.1.1 |
| Wallet SDK | 1.2.0 — **pin exactly**; npm `latest` still resolves to 1.1.0 |
| DApp Connector API | 4.0.1 |
| Proof server | 8.1.0 |
| Indexer | 4.3.5 (preview) / 4.3.3-hotfix (preprod) |
| Node | 1.0.1 (preview) / 1.0.2 (preprod, mainnet) |

Node.js **v22 or newer** — the SDK uses Iterator helpers and Node 20 crashes on first sync. npm v10+.

Re-check the matrix rather than trusting this table if more than a few weeks have passed.

## When something breaks

Work down this list:

1. `/midnight-expert:doctor` and `/midnight-tooling:doctor` if the Midnight Expert plugins are installed
2. [Fix version mismatch errors](https://docs.midnight.network/how-to/fix-version-mismatches) — check this early, it is usually the answer
3. [Decode 1010 transaction rejection errors](https://docs.midnight.network/how-to/decode-1010-transaction-rejection-errors)
4. Error references by layer: [Midnight.js](https://docs.midnight.network/sdks/error-reference/midnight-js) · [wallet SDK](https://docs.midnight.network/sdks/error-reference/wallet-sdk) · [DApp connector](https://docs.midnight.network/api-reference/error-reference/dapp-connector-errors) · [indexer](https://docs.midnight.network/api-reference/error-reference/indexer-errors) · [ledger](https://docs.midnight.network/api-reference/error-reference/ledger-errors) · [proof server](https://docs.midnight.network/api-reference/error-reference/proof-server-errors) · [node](https://docs.midnight.network/nodes/error-codes)
5. `/midnight-status-codes:lookup <code>` for any code across the ecosystem
6. [Compiler errors](https://docs.midnight.network/troubleshoot/compiler-errors) · [SDK integration issues](https://docs.midnight.network/sdks/troubleshoot) · [FAQ](https://docs.midnight.network/troubleshoot/faq) · [Support](https://docs.midnight.network/troubleshoot/getting-help)
7. Local network problems: the troubleshooting section of [Networks and environments](https://docs.midnight.network/guides/networks-and-environments)
